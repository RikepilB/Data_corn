# Requirements

What Field Shift must do, how we will know, and which issue delivers it. Index: [planning README](README.md).

## How to read this file

- **IDs.** `R1` to `R12` are the challenge requirements, numbered exactly as in [ARCHITECTURE](../architecture/ARCHITECTURE.md), section 1. `FR-nn` are functional requirements, `NFR-nn` non-functional ones, `SC-nn` rules about what the science may claim, and `CR-nn` submission and compliance rules.
- **Priority** is Must, Should or Could, from the cut lines in the [team action plan](../TEAM-ACTION-PLAN.es.md) (section 5) and the issue labels `must`, `should` and `could`. A Should that is cut falls back to `not-available` or `assumed`. It never breaks the Must path ([MVP](MVP.md), section 3).
- **Acceptance criteria** are copied from the "Done when" lists in the issues and from the tests in the [implementation plan](../superpowers/plans/2026-11-14-field-shift-mvp.md). No threshold is invented here. A threshold that is a team choice pending a mentor answer is marked as such.
- **Delivered by** lists the epic first, then the task issues. Links go to the [Data_corn backlog](https://github.com/RikepilB/Data_corn/issues).
- **The record length is not guaranteed.** The plan counts on a 1981-2025 record. Whether every POWER parameter covers all of it is still **to verify** (open item O1 at the end). Nothing below promises 45 years.

## 2. Functional requirements

### 2.1 Pipeline

| ID | Requirement | Priority | Acceptance criterion | Delivered by |
|---|---|---|---|---|
| FR-01 | Validate every ficha against the schema and the semantic rules before it is written | Must | `validate_ficha(doc)` raises one `FichaError` that lists every problem, schema errors first. Rules: exactly one `is_current` rotation; every `matrix[].rotation_id` exists; every rotation and year type has a cell; every non-null band, `planting` included, has p10 ≤ p50 ≤ p90; `n_corn_years` ≤ `n_years`; `critical_stage_stress_days` is null exactly when `n_corn_years` is 0. | FR-02 | Read NASA POWER daily climate for the field point, cached, with missing values as NaN | Must | `get_json` returns the cache if present, otherwise retries with exponential backoff on connection errors and 5xx, then writes the cache. `fetch_power_daily` returns the 8 columns with units read from the payload, one cache file per year. | FR-07 | Classify year types and compute the planting window from the POWER frame, with no new network calls | Must | Tests: a 45-year series splits 15, 15, 15; a year with a missing season is omitted; the label year uses April-September only; planting waits for warm soil and a frost-free week; the last spring frost is found. `planting_block` returns the schema's `all_years` and `by_year_type` parts. | [#6](https://github.com/RikepilB/Data_corn/issues/6); [#41](https://github.com/RikepilB/Data_corn/issues/41) |
| FR-08 | Build the rotation by year-type matrix with ranges and confidence | Must | Bands are numpy p10, p50 and p90 (linear) over non-NaN years. The critical-stage band uses corn years only.
